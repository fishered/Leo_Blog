过去几年，我在知乎、dev.to、博客园和其他平台写过不少内容。每个平台都有自己的编辑器、文章地址和内容规则。写的时候很方便，几年后再回头看，却很难回答一个简单的问题：**我的文章到底在哪里？**

建立这个博客，不只是换一个发布平台，更像是重新整理自己的工程档案。

## Markdown 是内容的原件

在这套博客里，Markdown 文件不是网页的附件，而是文章本身。标题、发布时间、标签和原始出处写在文件开头，正文保持为可读的纯文本。

```yaml
---
title: "文章标题"
published: 2026-07-24
tags: [Java, 工程实践]
draft: false
---
```

这意味着，即使以后不再使用当前的博客框架，文章依然可以被任何文本编辑器打开，也可以迁移到下一套工具。

## GitHub 是版本库，也是发布入口

每次提交都会触发自动构建：Markdown 被转换成静态 HTML，随后发布到 GitHub Pages。文章不需要数据库，也不依赖在线后台。

整个过程只有三个动作：

1. 写完 Markdown。
2. 提交并推送到 GitHub。
3. 等待自动部署完成。

Git 同时记录了每次修订。文章什么时候改过、改了什么，都可以准确追溯。

## 迁移不是简单复制

旧文章会保留最初发布的平台和日期。如果内容已经过时，我会增加说明；如果经过大幅重写，也会记录新的修订日期。

> 目标不是制造一个看起来很大的文章数量，而是留下真正值得再次阅读的内容。

这个博客会慢慢生长。第一篇文章的意义，就是为后面的整理工作放下一枚清楚的路标。
